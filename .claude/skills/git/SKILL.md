# Git 액션 워크플로우

git 관련 작업 전에 이 워크플로우를 따른다.

## Step 1 — 컨벤션 읽기

반드시 `AGENTS.md`의 "Git 컨벤션" 섹션을 읽고 시작한다.
이 저장소는 백엔드·프론트와 달리 `docs/conventions/`를 두지 않고 AGENTS.md 한 곳에 규칙을 모은다.

## Step 2 — 작업 유형 파악 및 실행

### 커밋

- 형식: `type: 제목`
- type은 `feat`/`fix`/`refactor`/`docs`/`test`/`chore`/`init`
- 제목은 한글, 마침표 없음
- `Co-Authored-By`, `Claude-Session` 등 AI 트레일러를 추가하지 않는다
- 작업 단위별로 커밋을 나눈다

### 이슈 생성

- 이슈 제목에 `type`이 들어가지 않도록 한다
- 구현 내용을 체크리스트로 작성한다
- 팀 공통 형식을 따른다

```markdown
## 어떤 기능인가요?
> 추가하려는 기능에 대해 간결하게 설명해주세요

## 📝 작업 상세 내용
- [ ] 구현 내용
- [ ] 구현 내용

## 📁 참고 자료 (선택)
```

### 브랜치 생성

- 형식: `{type}/#{이슈번호}-{작업내용(영어)}`
- **작업내용은 영어 소문자·하이픈으로 쓴다.** 한글을 쓰면 URL 인코딩 문제가 생긴다
- 반드시 이슈를 먼저 생성해 이슈번호를 확보한 뒤 브랜치를 만든다
- `main`에 직접 커밋이 쌓인 경우: 브랜치 생성 → main을 `origin/main`으로 리셋 → 브랜치 푸시

### PR 생성

- 제목 형식: `[{Type}/#{이슈번호}] {설명}`
- 연관 이슈를 반드시 연결한다
- 팀 공통 형식을 따른다

```markdown
## #️⃣연관된 이슈
> ex) #이슈번호

## 📝작업 내용
> 이번 PR에서 작업한 내용을 간략히 설명해주세요

## 💬리뷰 요구사항(선택)
> 리뷰어가 특별히 봐주었으면 하는 부분이 있다면 작성해주세요
```

- Squash Merge가 기본이다
- `main`에 직접 push하지 않는다

### 이슈-브랜치-PR 전체 흐름

```
이슈 생성 → 브랜치 생성 (이슈번호 포함) → 작업 및 커밋 → PR 생성 (이슈 연결) → 리뷰 → Squash Merge → 브랜치 삭제
```

## Step 3 — 자가 검증

- [ ] 커밋 메시지 type이 올바른가
- [ ] 브랜치명에 이슈번호가 포함됐고 작업내용이 영어인가
- [ ] PR 제목 형식이 `[{Type}/#{이슈번호}] {설명}`인가
- [ ] PR에 연관 이슈가 연결됐는가
- [ ] AI 트레일러가 없는가
