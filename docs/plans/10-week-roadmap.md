# 슬랑제 발표까지 10주 로드맵

> 작성일: 2026-09-28
> 기간: 2026-09-15 ~ 2026-11-21 (발표 11/21 토)
> 목표: 슬랑제에서 시연 가능한 상태 + 백엔드와 실제로 연결된 상태
> 인원: 2명 / 주당 10~20시간
> 참고: `docs/reference/db-schema.md`(API 계약), AGENTS.md(아키텍처, 배포 전 확인)

6주 로드맵(`6-week-roadmap.md`)을 10주로 늘리고 범위를 다시 잡았다.
계획은 바뀐다. 바뀌면 이 파일을 고치고 왜 바꿨는지 커밋 메시지에 남긴다.

| 바뀐 것 | 전 | 후 | 이유 |

### 배포를 범위에 넣은 이유

6주 로드맵은 배포를 뺐다. 그 판단의 전제는 **"프론트가 우리 서버를 직접 부를 일이 없다"** 였다.
프론트가 챗봇 화면을 만들기 시작해서 전제가 깨졌다.

지금은 이상현의 맥북이 켜져 있어야만 프론트가 챗봇 화면을 테스트할 수 있다.
발표 직전에 처음 배포하면 그날 처음 보는 문제를 그날 고쳐야 한다.
도커로 실행 환경을 고정하고 일찍 한 번 올려두는 쪽이 싸다.

**도커**는 실행 환경(파이썬 버전, 설치한 라이브러리, 설정)을 이미지 하나로 묶어
다른 컴퓨터에서 같게 실행하는 도구다.

### 배포에서 먼저 풀어야 하는 것: 인증

`app.py`의 `genai.Client()`는 인자가 없다. 지금은 `gcloud auth application-default login`으로
맥북에 저장된 개인 로그인 정보(ADC)를 SDK가 찾아 쓴다. **그 파일은 컨테이너 안에 없다.**
컨테이너만 만들어 돌리면 Vertex 403이 난다.

| 방법 | 판단 |
| --- | --- |
| 배포 환경의 서비스 계정 (Cloud Run 등) | 채택. 키 파일이 필요 없다 |
| 로컬 도커 테스트에 ADC 파일 마운트 | 3주차 확인용으로만 쓴다 |
| 서비스 계정 키 JSON을 이미지에 넣기 | 쓰지 않는다. 그 파일이 곧 비밀번호다(AGENTS.md 금지 사항) |

### AI 서버는 인터넷에 직접 노출하지 않는다

```
학생 브라우저 → 프론트(React) → 백엔드(Spring) → AI 서버(이 저장소) → Gemini
```

AGENTS.md 아키텍처에서 이미 정한 것이다. 프론트가 AI 서버를 직접 부르면 주소가 브라우저에
노출되고 누구나 우리 Gemini 비용으로 아무 질문이나 할 수 있다.
그래서 **백엔드 SSE 중계는 선택이 아니라 전제다.** 서준에게 "가능해?"가 아니라 "어떻게?"로 묻는다.

Cloud Run 같은 관리형 서비스는 기본이 인터넷 공개다. 쓰더라도 인증된 요청만 허용하도록 잠근다.
잠그는 방법은 백엔드가 어디에 올라가 있는지에 따라 갈린다(`db-schema.md` 5절 확인 목록).

### API 연결은 두 구간이고 레포가 다르다

코드는 그 코드를 실행하는 쪽 저장소에 둔다. 서버 A가 서버 B를 부르는 코드는 A에 있다.

| 구간 | 코드 위치 | 담당 |
| --- | --- | --- |
| 프론트 → 백엔드 | 프론트 저장소 | 우리 일이 아니다 |
| 백엔드 → AI 서버 (SSE 중계) | **백엔드 저장소 (Java/Spring)** | **미확정.** 아래 참고 |
| AI 서버 → 백엔드 API (`sync.py`, `tools.py`) | **이 저장소** | 이상현 |

**SSE 중계 담당이 확정되지 않았다.** 이상현이 맡는다면 백엔드 저장소에서 Java를 쓰게 되고,
그쪽 컨벤션을 따르고 서준과 파일 담당을 나눠야 한다. 이 저장소에 두면 안 된다.
실행하는 주체가 Spring이라 여기 있으면 아무도 돌리지 않는다.
4주차 시작 전에 확정한다. 이상현이 맡을 경우 학습 비용이 붙어 5주차 태스크를 하나 뺀다.

## 주차별 일정

주마다 태스크 3개. 주차는 화요일 시작 기준이다.
1~2주차는 끝났다. 자세한 내용은 `6-week-roadmap.md`에 남겨둔다.

### 1주차 (9/15~9/21) — 질문 수집과 준비 (완료)

학생 질문 59건 수집, 말투 v2 초안, `chunk.py` 초안, 백엔드 확인 목록 전달.

### 2주차 (9/22~9/28) — 고정 정보 답변 (완료)

고정 정보 시드 문서, BM25 인덱스 + `search.py`, 골든셋 78건 + `eval.py` + 1차 점수.
1차 점수: 함정 정답률 100%(20/20), 답변 채점 39.1%. 프롬프트는 v2를 유지한다.

### 3주차 (9/29~10/5) — 공지·행사 동기화와 도커

1. **가짜 공지·행사 API** (이승빈) — 실제 API와 같은 모양으로 응답한다. camelCase(`noticeId`, `applyEndAt`),
   날짜는 오프셋 없는 ISO8601이다. DB 컬럼명이 아니다. 삭제된 행·지난 행사·미발행 행사를 섞어 넣는다.
   **목업 행사 9건에 `isPublished`가 없다.** 백엔드 목록 API는 `is_deleted = 0 AND is_published = 1`로
   거르므로 필드를 추가한다. **주 중반까지 필요하다.** 이게 없으면 `sync.py`를 붙일 대상이 없다
2. **`sync.py`** (이상현) — 지금 `build_index.py`는 `test_data/*.json`을 파일로 직접 읽는다.
   이걸 HTTP 조회로 바꾼다. 나중에 주소만 실제 백엔드로 교체하는 것이 목적이다.
   `isDeleted` 필터는 `build_index.py`에 이미 있으므로 다시 만들지 않는다.
   새로 넣는 것은 **`isPublished` 필터**, 학기 표현 추출("2026-2학기"), 오래된 공지 경고다
3. **도커 이미지** (이상현) — `Dockerfile`, `.dockerignore`. 컨테이너로 띄워 SSE가 조각조각
   오는지 눈으로 확인한다. 인증은 ADC 파일 마운트로 임시 해결한다.
   `index/bm25.json`은 커밋되지 않으므로 이미지 빌드 중 `build_index.py`를 돌려 넣는다.
   `ENV=prod`로 데모 페이지가 닫히는지, `$PORT`를 읽는지 확인한다

**완료 기준**: 컨테이너로 띄운 서버가 최신 공지로 답한다. 삭제·미발행·지난 공지는 답에 나오지 않는다

**이번 주에 공유할 것**: 프론트에 SSE 명세(응답이 JSON 한 방이 아니다),
서준에게 배포 위치와 중계 방식 질문, 1차 점수표를 노션에 기록

### 4주차 (10/6~10/12) — 실시간 조회와 첫 배포 (마일스톤)

1. **가짜 재고 API** (이승빈) — 수량을 바꾸면 응답이 바로 바뀐다
2. **`tools.py` function calling** (이상현) — Gemini가 필요할 때 재고 조회 함수를 호출하게 한다.
   **function calling**은 모델이 "이건 내가 아는 게 아니라 조회해야 한다"고 판단하면
   우리가 등록해둔 함수를 대신 호출하게 하는 기능이다
3. **첫 배포 + 헤더 인증** (이상현) — 실제로 올리고 서준이 부를 수 있는 주소를 준다.
   `X-Internal-Token`, `X-User-Id` 검증을 붙인다. 지금은 계약에만 있고 양쪽 다 미구현이다.
   토큰은 `.env`로 받고 저장소에 올리지 않는다

**완료 기준**: "우산 지금 남았어요?"에 현재 수량으로 답한다. 서준이 배포된 주소로 호출에 성공한다

### 5주차 (10/13~10/19) — 백엔드 실연동과 학교 공지

1. **백엔드 실 API 연동** (이상현·이승빈) — 가짜 API 주소를 실제 백엔드로 교체한다.
   안 되면 가짜를 유지하고, 발표에서 실데이터라고 말하지 않는다.
   판단 회의를 이번 주 안에 한다. 6주 로드맵의 "4주차 말 판단 회의"를 여기로 옮긴 것이다
2. **SSE 중계 연결 확인** (담당 미확정) — 프론트 → 백엔드 → AI 서버로 실제 답변이 흐르는지 본다.
   백엔드가 응답을 모아뒀다 한 번에 보내면 스트리밍이 죽는다. 조각으로 도착하는지 확인한다
3. **학교 공지 목록 수집** (이상현) — robots.txt 확인 후 제목·게시일·링크만 하루 1~2회 수집해
   별도 인덱스에 저장한다. 본문은 가져오지 않는다

**완료 기준**: 학생 브라우저에서 질문해서 챗봇 답이 조각으로 도착한다. 학교 공지 목록이 쌓인다

### 6주차 (10/20~10/26) — 학교 공지 안내와 신뢰성

1. **학교 공지 링크 안내 답변** (이상현) — 학사 질문이 오면 수집한 목록에서 찾아
   제목·게시일·링크만 안내한다. 내용은 답하지 않는다
2. **"모르겠습니다" 강화** (이상현·이승빈) — 함정 문항과 실연동 후 나온 오답을 보고
   프롬프트와 시드 문서를 보강한다
3. **인덱스 갱신 스케줄** (이승빈) — 갱신이 멈추면 공지 수정이 반영되지 않는다.
   배포된 서버에서 주기적으로 재구축하게 한다

**완료 기준**: 학사 질문에 링크만 안내한다. 인덱스가 사람 손 없이 갱신된다

### 7주차 (10/27~11/2) — 기능 개발 마감

기능 개발은 **10/31까지**다. 이후에는 새 기능을 넣지 않는다.

1. **개인별 조회 여부 판단** (공동) — `X-User-Id`가 실제로 오면 "내 대여", "내 사물함 위치"가
   가능해진다. 되면 넣고, 안 되면 명시적으로 빼고 챗봇이 "로그인이 필요한 정보"라고 답하게 한다.
   애매하게 남겨두지 않는다
2. **2차 점수 측정 + 프롬프트 확정** (이상현) — 골든셋 78건을 이제 거의 다 돌릴 수 있다.
   2주차에는 API 조회·링크 안내 케이스를 잴 수 없었다. 1차 점수와 비교한다
3. **기능 동결** (공동) — 남은 것을 목록으로 만들고 발표 범위에서 뺀다

**완료 기준**: 골든셋 전체 점수표. 발표에 넣을 것과 뺄 것이 문서로 갈린다

### 8주차 (11/3~11/9) — QA·UT

1. **QA 시나리오 참여** (공동) — 팀 전체 QA에 챗봇 시나리오를 넣는다
2. **UT 질문 수집 → 골든셋 추가** (이상현) — 실제 사용자가 던진 질문이 가장 좋은 골든셋이다.
   우리가 예상하지 못한 표현이 여기서 나온다
3. **버그 수정만** (공동)

**완료 기준**: UT에서 나온 질문이 골든셋에 들어가고, 틀린 것이 목록으로 남는다

### 9주차 (11/10~11/16) — QA 결과 반영

1. **UT 지적 반영** (공동)
2. **발표 시나리오 10개 확정** (공동) — 세 장면(출처 표시, 실시간 조회, 모르면 모른다고)이
   모두 걸리게 한다
3. **백업 영상 녹화** (공동) — 인터넷 없이도 보여줄 수 있게

**완료 기준**: 시나리오 10개가 연속으로 통과한다. 백업 영상이 있다

### 10주차 (11/17~11/21) — 발표

1. **리허설 2회** (공동)
2. **최종 점검** (공동) — 배포 상태, 인덱스 갱신, 백업 영상
3. **발표** (11/21 토)

## 지표

| 지표 | 무엇 | 1차(2주차) | 목표 |
| --- | --- | --- | --- |
| 함정 정답률 | 답이 없는 질문 20건에 모른다고 답하는 비율 | 100% (20/20) | 16/20 이상 유지 |
| 답변 채점 | 정답요지가 답변에 들어있는 비율 | 39.1% | 7주차에 재측정 후 판단 |
| Recall@5 | 근거 문서가 검색 상위 5개에 드는 비율 | 문서형 32건 기준 측정 | 상향 |

답변 채점 39.1%는 채점 방식이 엄격한 결과이기도 하다.
숫자 토큰은 전부 일치해야 통과시키므로 사람이 쓴 정답요지의 표기와 어긋나면 떨어진다.
점수 자체보다 주차별 변화를 본다.

## 확인할 것

백엔드(서준)에 물어볼 것은 `docs/reference/db-schema.md` 5절에 모은다. 여기는 나머지만 둔다.

- [ ] (백엔드) 백엔드가 어디에 올라가 있는지. AI 서버를 그 옆에 붙이는 방법이 여기서 갈린다
- [ ] (백엔드) SSE 중계 방식과 담당. 응답을 모으지 않고 그대로 흘려보내야 한다
- [ ] (백엔드) `X-Internal-Token` 값을 어떻게 공유할지
- [ ] (프론트) 공지·행사 상세 페이지 주소 형식. 출처 링크를 만들 때 필요하다
- [ ] (학교) robots.txt에서 공지 목록 경로 허용 여부, RSS 제공 여부
- [ ] (팀) `POST /chat`과 노션 명세의 `/chat/messages` 중 어느 경로로 갈지
