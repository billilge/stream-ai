### 배포를 범위에 넣은 이유

6주 로드맵은 배포를 뺐다. 그 판단의 전제는 **"프론트가 우리 서버를 직접 부를 일이 없다"** 였다.
프론트가 챗봇 화면을 만들기 시작해서 전제가 깨졌다.

지금은 이상현의 맥북이 켜져 있어야만 프론트가 챗봇 화면을 테스트할 수 있다.
발표 직전에 처음 배포하면 그날 처음 보는 문제를 그날 고쳐야 한다.
도커로 실행 환경을 고정하고 일찍 한 번 올려두는 쪽이 싸다.

**도커**는 실행 환경(파이썬 버전, 설치한 라이브러리, 설정)을 이미지 하나로 묶어
다른 컴퓨터에서 같게 실행하는 도구다.

### 배포에서 먼저 풀어야 하는 것: 인증

`app.py`의 `genai.Client()`는 인자가 없다. 지금은 `gcloud auth application-default login`으로
맥북에 저장된 개인 로그인 정보(ADC)를 SDK가 찾아 쓴다. **그 파일은 컨테이너 안에 없다.**
컨테이너만 만들어 돌리면 Vertex 403이 난다.

| 방법 | 판단 |
| --- | --- |
| 배포 환경의 서비스 계정 (Cloud Run 등) | 채택. 키 파일이 필요 없다 |
| 로컬 도커 테스트에 ADC 파일 마운트 | 3주차 확인용으로만 쓴다 |
| 서비스 계정 키 JSON을 이미지에 넣기 | 쓰지 않는다. 그 파일이 곧 비밀번호다(AGENTS.md 금지 사항) |

### AI 서버는 인터넷에 직접 노출하지 않는다

```
학생 브라우저 → 프론트(React) → 백엔드(Spring) → AI 서버(이 저장소) → Gemini
```

AGENTS.md 아키텍처에서 이미 정한 것이다. 프론트가 AI 서버를 직접 부르면 주소가 브라우저에
노출되고 누구나 우리 Gemini 비용으로 아무 질문이나 할 수 있다.
그래서 **백엔드 SSE 중계는 선택이 아니라 전제다.** 서준에게 "가능해?"가 아니라 "어떻게?"로 묻는다.

Cloud Run 같은 관리형 서비스는 기본이 인터넷 공개다. 쓰더라도 인증된 요청만 허용하도록 잠근다.
잠그는 방법은 백엔드가 어디에 올라가 있는지에 따라 갈린다(`db-schema.md` 5절 확인 목록).

### API 연결은 두 구간이고 레포가 다르다

코드는 그 코드를 실행하는 쪽 저장소에 둔다. 서버 A가 서버 B를 부르는 코드는 A에 있다.

| 구간 | 코드 위치 | 담당 |
| --- | --- | --- |
| 프론트 → 백엔드 | 프론트 저장소 | 우리 일이 아니다 |
| 백엔드 → AI 서버 (SSE 중계) | **백엔드 저장소 (Java/Spring)** | **이상현.** 아래 참고 |
| AI 서버 → 백엔드 API (`sync.py`, `tools.py`) | **이 저장소** | 이상현 |

**SSE 중계 담당은 이상현이다.** 노션 API 명세서의 챗봇 엔드포인트 두 개가 모두
`서버 담당자: 이상현`으로 적혀 있다.

| 엔드포인트 | 내용 | 인증 |
| --- | --- | --- |
| `POST /chat/messages` | 질문을 받아 답변을 흘려보낸다(SSE 중계) | 필요 |
| `GET /chat/suggested-questions` | 챗봇 진입 화면의 추천 질문 목록 | 필요 |

즉 이상현은 **이 저장소(FastAPI)와 백엔드 저장소(Spring) 두 곳**에서 작업한다.
백엔드 저장소 쪽은 Java를 쓰고 그쪽 컨벤션을 따르며, 서준과 파일 담당을 나눠야 한다.
이 저장소에 두면 안 된다. 실행하는 주체가 Spring이라 여기 있으면 아무도 돌리지 않는다.

**두 엔드포인트는 주차가 다르다.** 2026-09-28에 `billilge/stream-server`를 확인한 결과다.

| 있는 것 | 뜻 |
| --- | --- |
| `ChatMessage.java`, `ChatMessageJpaEntity.java` → `chat_messages` 테이블 | 대화가 DB에 저장될 준비가 됐다. 9/21 회의 "문의기록은 DB에서만 남김"이 이것이다 |
| `sender_type` 칸 (10자) | user / model 구분. **백엔드가 대화 이력을 꺼내 보낼 수 있다** |
| `AppNoticeController` 등 Controller 7개 | 중계 Controller를 쓸 때 모양을 참고한다 |

| 없는 것 | 영향 |
| --- | --- |
| 챗봇 Controller | 이것이 이상현이 쓸 것이다. 3주차 |
| FAQ·추천 질문 테이블 (흔적 없음) | **`GET /chat/suggested-questions`를 지금 하면 읽을 데이터가 없다.** 관리자 페이지 완료(10월 말) 뒤인 7주차로 미룬다 |

Controller 7개는 모두 응답을 다 만들어 한 번에 주는 방식이다. **SSE 중계는 참고할 예시가 없다.**
파이썬만 해본 사람이 Java로 처음 쓰는 패턴이라 3주차에 못 끝낼 수 있다고 보고 잡는다.

## 주차별 일정

주마다 태스크 3개. 주차는 화요일 시작 기준이다.
1~2주차는 끝났다. 자세한 내용은 `6-week-roadmap.md`에 남겨둔다.

### 1주차 (9/15~9/21) — 질문 수집과 준비 (완료)

학생 질문 59건 수집, 말투 v2 초안, `chunk.py` 초안, 백엔드 확인 목록 전달.

### 2주차 (9/22~9/28) — 고정 정보 답변 (완료)

고정 정보 시드 문서, BM25 인덱스 + `search.py`, 골든셋 78건 + `eval.py` + 1차 점수.
1차 점수: 함정 정답률 100%(20/20), 답변 채점 39.1%. 프롬프트는 v2를 유지한다.

### 3주차 (9/29~10/5) — 도커와 백엔드 중계

이번 주는 **다른 사람을 막고 있는 것부터 푼다.** 프론트가 챗봇 화면을 만들고 있는데
지금은 이상현의 맥북이 켜져 있어야만 테스트할 수 있다. `sync.py`는 아무도 막지 않아 5주차로 미룬다.

1. **도커 이미지** (이상현) — `Dockerfile`, `.dockerignore`. 컨테이너로 띄워 SSE가 조각조각
   오는지 눈으로 확인한다. 인증은 ADC 파일 마운트로 임시 해결한다.
   `index/bm25.json`은 커밋되지 않으므로 이미지 빌드 중 `build_index.py`를 돌려 넣는다.
   `ENV=prod`로 데모 페이지가 닫히는지, `$PORT`를 읽는지 확인한다
2. **`POST /chat/messages` 중계 Controller** (이상현, **백엔드 저장소**) — AI 서버의 SSE를
   그대로 흘려보낸다. 모아뒀다 한 번에 보내면 스트리밍이 죽는다.
   **이번 주에 못 끝낼 수 있다.** Java가 처음이고 기존 Controller 7개에 SSE 예시가 없다.
   끝나면 프론트와 함께 프론트 → 백엔드 → AI 서버로 조각이 도착하는지 확인한다
3. **정규화 패턴 보강 + 전후 비교** (이승빈, 이슈 #25) — 실제 카톡 공지 4건으로 점수를 비교한다.
   목업으로는 정규화가 0%를 제거해 신호가 나오지 않는다.
   **가짜 공지·행사 API는 4주차로 미룬다.** `sync.py`가 5주차라 주 중반 마감이 사라졌다

**완료 기준**: 컨테이너로 띄운 서버가 SSE로 답한다. 정규화 전후 점수가 숫자로 나온다.
중계 Controller는 시작하고 어디까지 갔는지 기록한다

**순서를 이렇게 잡은 이유**: 도커를 먼저 해두면 중계가 안 될 때 "중계 코드가 틀렸나
우리 서버가 틀렸나"를 구분할 수 있다. 1번까지 확실한 상태를 만들고 2번으로 간다

**이번 주에 공유할 것**: 프론트에 SSE 명세(응답이 JSON 한 방이 아니다),
서준에게 배포 위치·중계 담당 확인, 1차 점수표를 노션에 기록

### 4주차 (10/6~10/12) — 실시간 조회와 첫 배포 (마일스톤)

1. **가짜 API 세 종** (이승빈) — 공지·행사·재고. 3주차에서 넘어온 공지·행사를 함께 만든다.
   실제 API와 같은 모양으로 응답한다. camelCase(`noticeId`, `applyEndAt`), 날짜는 오프셋 없는 ISO8601이다.
   DB 컬럼명이 아니다. 삭제된 행·지난 행사·미발행 행사를 섞어 넣는다.
   **목업 행사 9건에 `isPublished`가 없다.** 백엔드 목록 API는 `is_deleted = 0 AND is_published = 1`로
   거르므로 필드를 추가한다. 재고는 수량을 바꾸면 응답이 바로 바뀌어야 한다.
   **5주차 `sync.py`가 이것을 기다린다**
2. **`tools.py` function calling** (이상현) — Gemini가 필요할 때 재고 조회 함수를 호출하게 한다.
   **function calling**은 모델이 "이건 내가 아는 게 아니라 조회해야 한다"고 판단하면
   우리가 등록해둔 함수를 대신 호출하게 하는 기능이다
3. **첫 배포 + 헤더 인증** (이상현) — 실제로 올리고 서준이 부를 수 있는 주소를 준다.
   `X-Internal-Token`, `X-User-Id` 검증을 붙인다. 지금은 계약에만 있고 양쪽 다 미구현이다.
   토큰은 `.env`로 받고 저장소에 올리지 않는다

**완료 기준**: "우산 지금 남았어요?"에 현재 수량으로 답한다. 서준이 배포된 주소로 호출에 성공한다

### 5주차 (10/13~10/19) — 동기화와 백엔드 실연동

1. **`sync.py` + 백엔드 실 API 연동 판단** (이상현·이승빈) — 3주차에서 넘어왔다.
   지금 `build_index.py`는 `test_data/*.json`을 파일로 직접 읽는다(`build_index.py:76`). 이걸 HTTP 조회로 바꾼다.
   나중에 주소만 실제 백엔드로 교체하는 것이 목적이다.
   `isDeleted` 필터는 `build_index.py:80`에 이미 있으므로 다시 만들지 않는다.
   새로 넣는 것은 **`isPublished` 필터**, 학기 표현 추출("2026-2학기"), 오래된 공지 경고다.
   가짜 주소를 실제 백엔드로 바꿀 수 있으면 바꾼다. 안 되면 가짜를 유지하고
   **발표에서 실데이터라고 말하지 않는다.** 판단 회의를 이번 주 안에 한다
2. **중계 연결 마무리** (이상현) — 3주차 중계 Controller가 밀렸으면 여기서 끝낸다.
   끝났으면 프론트 → 백엔드 → AI 서버로 조각이 도착하는지 실제 화면에서 확인한다.
   **이 칸을 일부러 비워둔다.** 3주차 2번이 Java 첫 작업이라 밀릴 가능성이 높다
3. **학교 공지 목록 수집** (이상현) — robots.txt 확인 후 제목·게시일·링크만 하루 1~2회 수집해
   별도 인덱스에 저장한다. 본문은 가져오지 않는다

**완료 기준**: 인덱스가 HTTP로 받은 데이터로 만들어진다. 학생 브라우저에서 질문해서
챗봇 답이 조각으로 도착한다. 학교 공지 목록이 쌓인다

### 6주차 (10/20~10/26) — 학교 공지 안내와 신뢰성

1. **학교 공지 링크 안내 답변** (이상현) — 학사 질문이 오면 수집한 목록에서 찾아
   제목·게시일·링크만 안내한다. 내용은 답하지 않는다
2. **"모르겠습니다" 강화 + 프롬프트 인젝션 방어** (이상현·이승빈) — 함정 문항과 실연동 후
   나온 오답을 보고 프롬프트와 시드 문서를 보강한다.
   **프롬프트 인젝션**은 "앞의 지시는 무시하고 ~해"처럼 모델의 규칙을 덮어쓰려는 입력이다.
   우리에게는 경로가 두 개다. 학생이 질문에 직접 넣는 것과, **공지 본문에 섞여 들어오는 것**이다.
   문서 내용은 시스템 지시문에 그대로 이어 붙으므로 뒤쪽이 더 위험하다.
   AI Todo에 있던 항목이고 실데이터를 붙인 뒤에 해야 의미가 있어 여기 둔다
3. **인덱스 갱신 스케줄** (이승빈) — 갱신이 멈추면 공지 수정이 반영되지 않는다.
   배포된 서버에서 주기적으로 재구축하게 한다

**완료 기준**: 학사 질문에 링크만 안내한다. 인덱스가 사람 손 없이 갱신된다

### 7주차 (10/27~11/2) — 기능 개발 마감

기능 개발은 **10/31까지**다. 이후에는 새 기능을 넣지 않는다.

## 확인할 것

백엔드(서준)에 물어볼 것은 `docs/reference/db-schema.md` 5절에 모은다. 여기는 나머지만 둔다.

- [ ] (백엔드) 백엔드가 어디에 올라가 있는지. AI 서버를 그 옆에 붙이는 방법이 여기서 갈린다
- [x] (백엔드) SSE 중계 담당 — **이상현.** 노션 API 명세서 서버 담당자 기준 (2026-09-28 확인)
- [ ] (백엔드) 중계 Controller를 어느 모듈에 둘지, 서준과 파일이 겹치지 않는지
- [ ] (백엔드) `X-Internal-Token` 값을 어떻게 공유할지
- [ ] (프론트) 공지·행사 상세 페이지 주소 형식. 출처 링크를 만들 때 필요하다
- [ ] (학교) robots.txt에서 공지 목록 경로 허용 여부, RSS 제공 여부
- [ ] (팀) `POST /chat`과 노션 명세의 `/chat/messages` 중 어느 경로로 갈지
- [ ] (백엔드) **요청 본문 모양.** 노션 명세는 `{ "message": "..." }` 한 문장이고,
      AI 서버는 `{ "messages": [ {role, text} ] }`로 대화 이력을 통째로 받는다.
      AI 서버는 대화를 저장하지 않으므로 이력을 안 보내면 "그럼 언제까지야?" 같은 후속 질문이 깨진다.
      백엔드가 DB에서 이력을 꺼내 채워 보내야 한다. SSE와는 별개 문제다.
      **`chat_messages` 테이블과 `sender_type` 칸이 이미 있어 꺼낼 수는 있다**(2026-09-28 확인).
      몇 턴까지 보낼지는 정해야 한다. 다 보내면 토큰 비용이 계속 늘어난다
- [ ] (팀) **`relatedQuestions`를 유지할지.** 노션 명세의 응답에 있는데 AI 서버는 만들지 않는다.
      만들려면 답변마다 추가 생성이 필요해 응답이 느려지고 비용이 든다. 빼는 쪽을 권한다
- [ ] (백엔드) 노션 「메시지 전송」의 404 예시가 `WORK_SCHEDULE_NOT_FOUND`(근무 시간표)로 적혀 있다.
      복붙 오류로 보인다. 챗봇에 404가 필요한지부터 정한다
