# 슬랑제 발표까지 8주 로드맵

> 작성일: 2026-09-11
> 목표: 슬랑제에서 시연 가능한 상태
> 인원: 2명 / 주당 10~20시간

학생회 공지·행사는 검색해서 출처와 함께 답하고, 빌릴게 재고는 백엔드에 실시간으로
물어보는 챗봇을 만든다. 매주 끝에 눈으로 확인할 수 있는 결과가 하나씩 남도록 짰다.

계획은 바뀐다. 바뀌면 이 파일을 고치고 왜 바꿨는지 커밋 메시지에 남긴다.

## 답변 경로는 두 갈래

| 갈래 | 대상 | 방식 |
| --- | --- | --- |
| 검색 | 공지 본문, 행사 안내, 빌릴게 이용 방법·품목 목록 | RAG 인덱싱 |
| 실시간 | 빌릴게 재고 | 매번 백엔드 조회 |

서비스 단위가 아니라 질문 단위로 갈린다.
"우산 어떻게 빌려요"는 검색이고 "우산 지금 남았어요"는 실시간이다.

## 막힌 것을 기다리지 않는다

`search.py`는 1주차에 하드코딩을 반환하는 스텁으로 먼저 만들고 4주차에 진짜로 바꾼다.
빌릴게 재고도 같은 방식이다. 5주차에 가짜 응답으로 붙이고, 백엔드가 나오면 주소만 바꿔 끼운다.

덕분에 백엔드가 늦어도 일정이 밀리지 않고, 최악의 경우 가짜 데이터로도 발표할 수 있다.
다만 그 경우 발표에서 실데이터라고 말하지 않는다.

## 시드 데이터를 직접 만들기 때문에 생기는 함정

문서를 우리가 쓰면 그 문서를 보고 평가 질문을 만들게 된다. 그러면 다 맞히고 점수는 의미가 없다.

**순서를 뒤집는다.** 실제 학생에게 먼저 질문을 받고, 그 질문에 답이 되도록 시드 문서를 쓴다.
답이 없는 질문 20개는 문서를 만들지 않고 그대로 남겨둔다. 모른다고 답하는지 보는 문항이다.

## 주차별 일정

### 1주차 — 기반

서로 안 기다리고 일할 수 있는 상태 만들기.

- 이상현: `search.py` 스텁을 `app.py`에 연결, `prompts/system_v1.md` 초안
- 이승빈: 학생회와 시드 데이터 범위 합의, 실제 학생 질문 수집 시작 (40건 목표)
- 공동: 백엔드 API 계약 확정. 구현은 나중이어도 모양은 지금 정해야 가짜 응답을 만들 수 있다

**완료 기준**: 스텁 문서로 출처 달린 답변이 스트리밍되고, 학생 질문 40건이 모인다

### 2주차 — 시드

모은 질문에 답이 되도록 문서를 쓴다.

- 이승빈: 시드 문서 50건 (공지 20, 행사 10, 빌릴게 이용 안내·품목 20)
- 이상현: `chunk.py` — 공지 500~800자에 앞뒤 100자 중복, 표는 통째로. 게시일·유효기간 필수

**완료 기준**: `docs/seed/`에 문서 50건이 쌓이고 청킹이 돌아간다

### 3주차 — 인덱스

검색 가능한 형태로 만들고 채점 기준을 확정.

- 이승빈: `build_index.py`로 BM25 인덱스, `index/current` 링크 교체
- 이상현: `eval/golden.jsonl` 60건. 답이 없는 함정 문항 20개 포함

**완료 기준**: `index/build_*/`가 생성되고 골든셋 60건(함정 20)이 채워진다

### 4주차 — 연결 (마일스톤)

처음으로 진짜 챗봇이 되는 주.

- 이승빈: `search.py` 실제 구현으로 스텁 교체. 인터페이스가 같아서 `app.py`는 손대지 않는다
- 이상현: 검색 결과로 답변 생성, 데모 페이지 정비

**완료 기준**: 브라우저에서 질문 → 시드 문서 검색 → 출처 달린 답변

### 5주차 — 측정

감이 아니라 점수로 판단하기 시작.

- 이상현: `eval.py` — Recall@5, 함정 문항 정답률. 기준선을 기록해둔다
- 이승빈: 빌릴게 재고 조회 가짜 서버. 1주차 계약 모양 그대로 응답하게 만든다

**완료 기준**: 1차 점수표가 남고, 가짜 재고 API가 계약대로 응답한다

### 6주차 — 실시간 (마일스톤)

빌릴게 재고를 실시간으로 답하기.

- 이상현: `tools.py` — Gemini function calling으로 재고 조회 연결
- 이승빈: `sync.py`로 백엔드 공지·행사 동기화, 재고 API를 가짜에서 실제로 교체

**완료 기준**: "우산 지금 남았어요?"에 현재 수량으로 답한다
백엔드가 늦으면 가짜를 유지하고 넘어간다

### 7주차 — 신뢰성

모르는 걸 아는 척하지 않게 만들고 발표 장면 확정.

- 이상현: 학사 정보 링크 안내, "모르겠습니다" 강화, `system_v2.md`, 발표용 질문 10개
- 이승빈: 시나리오가 걸리는 문서 보강, 게시일·유효기간으로 지난 학기 공지 거르기

**완료 기준**: 함정 문항 20건 중 16건 이상에서 모른다고 답하고, 시나리오 10개가 납득할 만하다

### 8주차 — 발표

- 리허설 2회, 화면 녹화본을 백업으로 준비
- 남은 버그 수정. **새 기능은 넣지 않는다**

**완료 기준**: 인터넷 없이도 돌아가는 데모와 백업 영상

## 발표에 꼭 넣을 세 장면

1. **출처를 달고 답한다** — 문서 제목·게시일·링크를 함께 보여준다. 지어낸 말이 아니라는 증거다
2. **지금 값을 물어본다** — 재고를 바꾼 뒤 다시 물으면 답이 바뀐다. 인덱스가 아니라 실시간 조회라는 증거다
3. **모르는 건 모른다고 한다** — 가장 설득력 있는 장면. 20문항으로 측정했다고 말할 수 있다

## 미리 잡아둬야 할 위험

- **시드를 우리끼리 만들면 평가가 거짓말을 한다.** 질문 먼저, 문서 나중 순서를 지킨다
- **학생회 협조가 늦어진다.** 1주차에 범위 합의가 안 되면 2주차가 빈다. 팀이 초안을 쓰고 검수만 받는 쪽으로 돌린다
- **백엔드가 6주차에 안 나온다.** 가짜로 개발하니 일정은 안 밀린다. 6주차 말에 실연동 여부를 확정하고 발표 대본을 그에 맞춘다
- **골든셋을 미룬다.** 3주차까지 60건을 못 채우면 5주차 측정이 통째로 무의미해진다

## 8주에서 뺀 것

| 항목 | 이유 |

| 개인별 데이터 | 내 대여·내 신청은 인증이 필요해 제외. 재고처럼 공용인 값만 |
| 아카이빙·게시판·열린피드백 | 데이터가 아직 없음. 공지·행사·빌릴게에 집중 |
| 벡터 검색 | BM25 기준선을 먼저 세운 뒤 평가로 판단 |
| 인덱스 자동 갱신 | 8주 동안은 수동 빌드로 충분 |

## AGENTS.md와 다른 점 하나

AGENTS.md는 골든셋을 100~150건으로 정해두지만 이 일정에서는 **60건(함정 20 포함)** 으로 줄였다.
주 10~20시간에 8주라면 100건을 채우다 다른 작업이 밀린다.
함정 20개는 줄이지 않는다. 환각 측정의 최소 단위다.
발표 후 운영에 들어갈 때 100~150건으로 늘린다.
