# 슬랑제 발표까지 6주 로드맵

> 작성일: 2026-09-15
> 수정일: 2026-09-20 (사물함 범위 편입, 1주차 3번 태스크 조정)
> 기간: 2026-09-15 ~ 2026-10-26
> 목표: 슬랑제에서 시연 가능한 상태
> 인원: 2명 / 주당 10~20시간
> 참고: `docs/reference/db-schema.md` (백엔드 DB 스키마)

8주 로드맵(`8-week-roadmap.md`)을 6주로 줄이고 순서를 다시 잡았다.
계획은 바뀐다. 바뀌면 이 파일을 고치고 왜 바꿨는지 커밋 메시지에 남긴다.

## 순서

| 단계 | 내용 | 데이터 출처 |
| --- | --- | --- |
| 1 | 고정 정보 답변 + 말투 교정 | `docs/seed/` (직접 작성) |
| 2 | 학생회 공지·행사 답변 | 시드 → 백엔드 API (`notices`, `events`) |
| 3 | 빌릴게 재고·사물함 잔여 실시간 조회 | 가짜 API → 백엔드 API (`items.count`, `lockers`) |
| 4 | 학교 공지 링크 안내 | 학교 홈페이지 공지 목록 수집 |

말투 교정은 프롬프트 파일만 고치는 일이라 1주차에 초안을 만든다.
확인 질문 10개에서 v2가 나아서 1주차에 바로 적용했다.
다만 말투를 고치다 "모르면 모른다고 답하기"가 약해질 수 있어서, 2주차 골든셋 점수로 v1과 다시 비교하고 떨어지면 되돌린다.

학교 공지 목록 수집은 3주차에 당겨서 시작하고, 답변 연결은 5주차에 한다.
별도 허락은 받지 않는다. 대신 robots.txt를 확인하고 목록만 하루 1~2회 가져온다(AGENTS.md 금지 사항).

### 고정 정보는 DB에 없다

간식 행사 장소, 빌릴게 사용 방법처럼 거의 바뀌지 않는 정보다.
`items` 테이블에는 이름·종류·수량만 있고 이용 방법 칸이 없다.
그래서 `docs/seed/`에 문서로 쓰고 `유효기간`은 비워둔다.
프롬프트에 직접 넣지 않는 이유는 출처(제목·게시일·링크)를 똑같이 표시하기 위해서다.

### 사물함은 개인별 항목만 뺀다

처음에는 사물함 전체를 인증이 필요하다는 이유로 제외했다. 1주차에 받은 학생 질문 59건 중
사물함이 10건이어서 뺄 근거가 없어졌다. 다만 사물함 질문은 두 종류로 갈린다.

- **인증이 필요 없다**: 신청 기간·방법, 구역별 잔여 수량.
  잔여 수량은 개인 정보가 아니라 빌릴게 재고와 같은 실시간 데이터고, 신청 기간·방법은 공지에 있으니 문서형이다
- **인증이 필요하다**: "내가 신청한 사물함 위치", "내가 놓치고 있는 일정" 같은 개인별 조회

앞쪽만 6주 범위에 넣는다. 뒤쪽은 인증 헤더가 확정된 뒤로 남긴다(`users.json`도 그때 쓴다).

### 학교 공지는 내용을 답하지 않는다

제목·게시일·링크만 안내한다(AGENTS.md "학교 공식 정보를 직접 답하지 않는 이유").
그래서 본문은 수집하지 않고 목록만 하루 1~2회 가져온다.
학생회 문서와 섞이지 않게 별도 인덱스로 둔다.

## 주차별 일정

주마다 태스크 3개. 주차는 화요일 시작 기준이다.

### 1주차 (9/15~9/21) — 질문 수집과 준비

1. **학생 질문 40건 수집** (이승빈) — 학생이 쓴 표현 그대로 받는다. 문서는 아직 쓰지 않는다
2. **말투 교정 v2 초안** (이상현) — `prompts/system_v2.md`. 스텁 문서로 확인 질문 10개(답이 없는 질문 3개 포함)를 직접 돌려본다
3. **백엔드 확인 사항 전달 + `chunk.py`** (이상현) — 응답 모양을 우리끼리 정할 수는 없다.
   서준이 답을 줘야 확정되므로, 물어볼 목록을 `db-schema.md` 5절에 모아 전달하는 것까지가 이번 주 몫이다.
   `chunk.py`는 API 필드명과 무관하다(그 변환은 3주차 `sync.py`가 맡는다). 스키마 기준으로 지금 쓴다.
   청킹은 공지 500~800자에 앞뒤 100자 중복, 표는 통째로, 게시일 필수

**완료 기준**: 학생 질문 40건, v2 초안, 백엔드 확인 목록 전달, `chunk.py`

### 2주차 (9/22~9/28) — 고정 정보 답변

1. **고정 정보 시드 문서** (이승빈) — 1주차 질문에 답이 되도록 빌릴게 사용법·행사 장소 등을 `docs/seed/`에 쓴다
2. **BM25 인덱스 + `search.py` 실제 구현** (이승빈) — `build_index.py`로 인덱스를 만들고 스텁을 교체한다
3. **골든셋 60건 + `eval.py` + v1/v2 비교** (이상현) — 함정 20건 포함. 1차 점수(Recall@5, 함정 정답률)를 기록하고,
   v2가 v1보다 떨어지면 v1으로 되돌린다

**완료 기준**: "빌릴게 어떻게 써요?"에 출처 달린 답변, 1차 점수표, 프롬프트 버전 확정

### 3주차 (9/29~10/5) — 학생회 공지·행사

1. **가짜 공지·행사 API** (이승빈) — 스키마 모양 그대로 응답한다. 삭제된 행과 지난 행사도 섞어 넣는다
2. **`sync.py` + 지난 공지 거르기** (이승빈·이상현) — `is_deleted` 제외, 학기 표현 추출, 오래된 공지 경고
3. **학교 공지 목록 수집** (이상현) — robots.txt 확인 후 제목·게시일·링크만 수집해 별도 인덱스로 저장한다

**완료 기준**: 삭제·지난 공지를 거르고 최신 공지로 답한다. 학교 공지 목록이 쌓인다

### 4주차 (10/6~10/12) — 빌릴게 재고 실시간 (마일스톤)

1. **가짜 재고 API** (이승빈) — 수량을 바꾸면 응답이 바로 바뀐다. 백엔드가 나오면 실제 주소로 교체
2. **`tools.py` function calling** (이상현) — Gemini가 필요할 때 재고 조회 함수를 호출하게 한다
3. **4주차 말 판단 회의** (공동) — 백엔드 실연동 여부를 확정한다. 안 되면 가짜 API를 유지하고,
   발표에서 실데이터라고 말하지 않는다

**완료 기준**: "우산 지금 남았어요?"에 현재 수량으로 답한다

### 5주차 (10/13~10/19) — 학교 공지 링크 안내와 신뢰성

1. **학교 공지 링크 안내 답변** (이상현) — 학사 질문이 오면 수집한 목록에서 찾아 제목·게시일·링크만 안내한다
2. **"모르겠습니다" 강화** (이상현·이승빈) — 함정 문항 결과를 보고 프롬프트와 문서를 보강한다
3. **발표 질문 10개 + 문서 보강** (공동) — 발표 세 장면(출처, 실시간, 모르면 모른다고)이 모두 걸리게 한다

**완료 기준**: 함정 문항 20건 중 16건 이상에서 모른다고 답하고, 시나리오 10개가 납득할 만하다

### 6주차 (10/20~10/26) — 발표

1. **리허설 2회** (공동)
2. **백업 영상 녹화** (공동) — 인터넷 없이도 보여줄 수 있게
3. **버그 수정만** (공동) — 새 기능은 넣지 않는다

**완료 기준**: 인터넷 없이도 돌아가는 데모와 백업 영상

## DB 스키마에서 나온 제약

자세한 내용은 `docs/reference/db-schema.md`.

- **삭제 필터**: `notices`, `events`는 `is_deleted = 1`인 행을 인덱싱하지 않는다
- **공지에 유효기간이 없다**: `created_at`만 있다. 제목·본문에서 "2026-2학기" 같은 표현을 뽑고,
  오래된 공지는 답변에 경고를 붙인다
- **행사 유효기간**: `apply_end_at`(신청 마감), `event_end_at`(행사 종료)을 쓴다.
  "지금 신청 가능?"은 `recruit_status`보다 `apply_end_at`과 현재 시각 비교가 안전하다
- **재고는 인덱싱 금지**: `items.name`은 검색 대상, `items.count`는 실시간 조회만
- **첨부파일은 파싱하지 않는다**: 링크로만 안내한다
- **동기화는 전체 재구축**: 스키마 문서는 `updatedAfter` 증분 동기화를 제안하지만,
  AGENTS.md대로 매번 전체를 다시 만든다. 삭제가 자동으로 반영되어 더 단순하다

## 확인할 것

백엔드(서준)에 물어볼 것은 `docs/reference/db-schema.md` 5절로 모았다.
두 군데에 나뉘어 있으면 한쪽만 갱신되어 어긋난다. 여기는 나머지만 남긴다.

- [ ] (프론트) 공지·행사 상세 페이지 주소 형식. 출처 링크를 만들 때 필요하다
- [ ] (학교) robots.txt에서 공지 목록 경로 허용 여부, RSS 제공 여부
- [ ] (공동) 학교 공지 수집 파일 이름과 담당

## 6주에서 뺀 것

| 항목 | 이유 |
| --- | --- |
| 배포 | 로컬 실행과 화면 공유로 대체. 배포 전 확인 목록은 AGENTS.md 참고 |
| 개인별 데이터 | 내 대여·내 신청·내 사물함 위치는 인증이 필요해 제외. 사물함 신청 기간·방법·잔여 수량은 범위에 넣는다 |
| `archives`, `open_feedbacks` | 데이터가 아직 없음 |
| 증분 동기화 | 전체 재구축으로 충분 |
| 벡터 검색 | BM25 기준선을 먼저 세운 뒤 평가로 판단 |
| 인덱스 자동 갱신 | 6주 동안은 수동 빌드로 충분 |

골든셋은 60건(함정 20 포함)으로 유지한다. 함정 20개는 줄이지 않는다.
